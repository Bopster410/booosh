# boosh

> Дружелюбный установщик минималистичного терминала **Ghostty + fish**: выбираешь внешний вид, шорткаты, тему, шрифт,
> курсор и редактор в меню со стрелками **с предпросмотром на лету**, потом добавляешь необязательные наборы
> («packs») для git и docker.

*[Read in English](README.md)*

```
Cursor style: (↑/↓ move, Enter select)
    block         filled box, the classic terminal cursor
    bar           thin vertical line, like in text editors
  ❯ underline     a line under the character
    block_hollow  outline of a box (shown when the window is unfocused)
  ┌─ preview ──────────────────────────────────
  │  live: your real cursor, underline, steady
  │   ~/app main $ git status
  │  blinking follows the next question (now: no)
  └────────────────────────────────────────────
```

`boosh` собирает конфиг Ghostty из небольших читаемых частей (пресет внешнего вида, пресет шорткатов и несколько
параметров), подключает конфиг редактора и всё делает обратимым: проверяет результат (если Ghostty установлен) через
`ghostty +validate-config` перед записью, делает бэкапы того, что заменяет, и никогда не правит твой `~/.bashrc`.

## Возможности

- **Меню со стрелками на чистом bash.** Без зависимостей (без `fzf` и `gum`). По коду рассчитано на bash 3.2+
  (см. [Совместимость](#совместимость)).
- **Предпросмотр на лету** под вариантами:
  - *тема*: образцы цветов в рамках из файлов тем самого Ghostty, светлая и тёмная рядом;
  - *шорткаты*: примеры клавиш для выбранного пресета;
  - *форма курсора и мигание*: **настоящий курсор терминала** меняет форму и мигает, пока ты двигаешься по пунктам;
  - *шрифт*: начертания и файл установленного шрифта;
  - *лигатуры* и *прозрачность фона*: иллюстрации (прозрачность это смешивание фона темы с «рабочим столом»).
- **Ползунки** для размера шрифта (8–32, шаг 0.5) и прозрачности фона (0.3–1, шаг 0.05).
- **Пресеты**: три внешних вида (`minimal`, `classic`, `borderless`) и два набора шорткатов (`alt`, `default`).
- **Выбор редактора**: `vim` или `nano` (готовый конфиг для каждого) или никакого. Новый редактор это одна папка.
- **Свой небольшой prompt для fish**: две строки, настраивается одной командой (git-информация в нём приходит с набором `git`), без менеджера плагинов
  (см. [Prompt](#prompt)). Либо оставить стандартный prompt fish или свой плагин.
- **Шпаргалка**: markdown-таблица твоих клавиш, собранная ровно под выбранную конфигурацию.
- **Наборы (packs)**: необязательные настройки терминала поверх базы. Есть `git` и `docker`. Каждый набор только
  кладёт файлы туда, откуда их и так читают программы, а `./pack remove` убирает их обратно.
- **Без вопросов**: у каждого вопроса есть флаг, поэтому работает и в скриптах, и на новой машине.
- **Безопасно**: стабильное ядро вне репозитория, проверка до применения, снимок (поколение) на каждую установку с
  `--rollback`, `--check`, `--uninstall`, перенос твоего старого конфига, бэкапы `.bak`, `--dry-run`, настройки git не
  перезаписываются молча (см. [Безопасное применение](#безопасное-применение)).

## Быстрый старт

```bash
git clone https://github.com/Bopster410/booosh.git
cd booosh

./bootstrap.sh --dry-run     # по желанию: что будет установлено (fish, vim)
./install.sh                 # интерактивное меню
./pack list                  # необязательные наборы для git, docker, ...
```

Перезагрузи конфиг Ghostty через `ctrl+shift+,` (или перезапусти). `./install.sh` можно запускать снова в любое время,
чтобы изменить выбор: прошлые ответы будут значениями по умолчанию в меню.

Примеры без вопросов:

```bash
./install.sh --yes                                   # прошлый выбор, иначе значения по умолчанию
./install.sh --preset borderless --theme nord --font-size 15 --editor nano
./install.sh --keys default                          # только стандартные клавиши Ghostty
./install.sh --only prompt                           # только prompt, Ghostty и редактор не трогать
./install.sh --print                                 # показать сгенерированный конфиг, ничего не писать
./install.sh --cheatsheet                            # напечатать шпаргалку по клавишам
./pack add git docker --none                         # наборы без необязательных частей и программ
```

## Что можно выбрать

| Вопрос | Варианты | Примечание |
|---|---|---|
| Пресет внешнего вида | `minimal`, `classic`, `borderless` | `minimal`: тонкий заголовок с текущей папкой, таб-бар снизу. `classic`: почти стоковый Ghostty. `borderless`: без заголовка и рамки. |
| Пресет шорткатов | `alt`, `default` | `alt` **добавляет** короткие клавиши на `Alt` (например `Alt+→` сплит, `Alt+T` новый таб) к стандартным. `default` ничего не добавляет. |
| Цветовая тема | `auto`, `mocha`, `rose-pine`, `kanagawa`, `tokyonight`, `gruvbox`, `nord`, любая тема Ghostty | `auto` это Catppuccin Latte/Mocha, следует за светлой/тёмной темой системы. |
| Шрифт | встроенный JetBrains Mono, установленные моноширинные или введённое имя | Неизвестное имя заменяется на JetBrains Mono. |
| Размер шрифта | 8 – 32, шаг 0.5 | ползунок |
| Лигатуры | да / нет | «нет» добавляет `font-feature = -calt`. |
| Форма курсора | `block`, `bar`, `underline`, `block_hollow` | живой предпросмотр |
| Мигание курсора | да / нет | живой предпросмотр |
| Прозрачность фона | 0.3 – 1.0 | ползунок; нужен композитор |
| Prompt оболочки | `boosh`, `default` | `boosh`: prompt, описанный [ниже](#prompt). `default`: стандартный prompt fish, ничего не ставится. |
| Редактор по умолчанию | `vim`, `nano`, `none` | подключает конфиг и ставит `EDITOR` в fish |

Модификатор пресета `alt` в меню не спрашивается: используй `--mod super` (например на Mac) или `--mod ctrl+alt`.
Как выглядит сгенерированная шпаргалка, смотри в [`docs/example-cheatsheet.md`](docs/example-cheatsheet.md).

### Пресеты шорткатов на примерах

| Действие | Стандартный Ghostty (есть в обоих пресетах) | Добавляет `alt` |
|---|---|---|
| Сплит | `Ctrl+Shift+O` / `Ctrl+Shift+E` | `Alt+←↑↓→` |
| Фокус на сплит | `Ctrl+Alt+←↑↓→` | `Alt+Shift+←↑↓→` |
| Размер сплита | `Super+Ctrl+Shift+←↑↓→` | `Alt+R`, потом стрелка |
| Развернуть сплит | `Ctrl+Shift+Enter` | `Alt+Z` |
| Новый таб | `Ctrl+Shift+T` | `Alt+T` |
| Закрыть сплит | (в списке нет) | `Alt+W` |
| Переключить таб | `Ctrl+PgUp` / `Ctrl+PgDn` | `Alt+[` / `Alt+]` |

Буквенные шорткаты привязаны к **физическим клавишам**, поэтому работают на любой раскладке (например, русской).
Цена: с `alt` стрелки с `Alt` перестают доходить до оболочки (в fish ими ходят по истории директорий и по токенам
истории); слова по-прежнему листаются `Ctrl`+стрелки.

## Наборы (packs)

```
$ ./pack list
  docker   available  fish abbreviations for docker and compose (d, dps, dcup, dcl...)
  git      available  fish abbreviations (gst, gd, gl...), safe git defaults, git info in the boosh prompt

$ ./pack add git                  # в терминале: один чек-лист опций пака (Space отмечает, Enter подтверждает)
$ ./pack add git --tag --delta    # тот же выбор флагами (это же путь для скриптов)
$ ./pack status                   # проверка состояния
$ ./pack remove git               # убирает файлы обратно; спросит про программы, которые поставил сам pack
```

**Опции.** Всё необязательное в наборе это *опция*, и выбирается она одинаково, чем бы ни была: **частью** (необязательная
папка набора, например `gtag`) или **утилитой** (необязательная программа, например `lazygit` или `delta`). В терминале
`./pack add ИМЯ` показывает один чек-лист того, что ещё не включено; в остальных случаях опции это флаги: `--tag`,
`--delta`, ... , `--all` (все опции), `--none` (никаких и без вопроса), `--with-tools` / `--no-tools` (все утилиты / ни
одной). Без терминала и без флагов необязательное не трогается, а каждая пропущенная опция называется. Выбор
запоминается: повторный `./pack add ИМЯ` его сохраняет, `./pack remove ИМЯ --ОПЦИЯ` выключает одну опцию (часть
разлинковывается; у утилиты отключаются её настройки git), а `./pack show ИМЯ`
показывает опции с состоянием и, для утилиты, как она ставилась бы здесь.

Набор это папка каталога (или корень репозитория):

| Файл | Что делает |
|---|---|
| `pack.conf` | `DESCRIPTION=...`, `API=1` (формат набора; набор, которому нужен более новый, отклоняется) и необязательные строки `TOOL=команда\|пакет brew\|пакет apt\|описание`. Для обычного плагина fisher не нужен. |
| `fish.fish` | линкуется в `~/.config/fish/conf.d/pack-<имя>.fish` (аббревиатуры, функции). |
| `functions/*.fish` | каждый линкуется в `~/.config/fish/functions/` (функции fish с автозагрузкой). |
| `completions/*.fish` | каждый линкуется в `~/.config/fish/completions/` (автодополнение по tab). |
| `conf.d/*.fish`, `themes/*.theme` | остальная раскладка fisher: линкуются по имени в `~/.config/fish/conf.d/` и `themes/`. |
| `extras/ИМЯ/` | **необязательная часть** со своим `extra.conf` (`DESCRIPTION=...`) и `fish.fish`, `functions/`, `completions/`. Ставится только по запросу: `./pack add ПАК --ИМЯ`; отдельно убирается `./pack remove ПАК --ИМЯ`. Обычный `./pack add ПАК` сохраняет уже установленные части. |
| `gitconfig` | линкуется в `~/.config/git/pack-<имя>.conf` и подключается одной строкой `include.path`. |
| `gitconfig.<tool>` | то же, но **только пока `<tool>` есть в `PATH`** (например `delta` как pager для git). |

Правила безопасности, заложенные в `pack`:

- Настройка git, которая у тебя уже задана другим значением, **выводится в отчёте** и не перезаписывается, пока не
  передан `--yes`.
- `delta` настраивается в отдельном файле, поэтому удаление программы не оставит сломанный `git diff`;
  `./pack status` предупредит, а `./pack add git` выключит этот файл.
- Чужие файлы (обычный файл на месте ссылки, симлинк на что-то другое) переносятся в бэкап или пропускаются.
- **Удаление программ.** `pack` записывает каждую программу, которую поставил сам (`~/.config/boosh/tools`). При удалении
  пака или при отключении утилиты (`./pack remove ИМЯ --УТИЛИТА`) он предлагает удалить именно их (в терминале вопрос
  «да/нет»; `--purge-tools` отвечает «да», `--keep-tools` отвечает «нет»; без терминала и без флага программы остаются, а
  команда для удаления выводится). Программа, которая была на машине до пака, не удаляется никогда, с флагами или без, а
  программа, которую использует другой установленный пак, остаётся, пока не будет удалён последний из них.
- **Какой пакетный менеджер?** Он определяется, а не настраивается: для каждой выбранной утилиты, которой нет, берётся
  Homebrew, если он установлен (в `PATH` или в одном из обычных мест) и у утилиты есть пакет Homebrew; иначе `apt`, если там
  есть пакет (`sudo` объявляется заранее); иначе ничего не ставится, а предупреждение объясняет причину (нет менеджера
  пакетов, пакет есть только в Homebrew, а его нет, ...), чтобы можно было поставить самому. Два менеджера молча не
  смешиваются, а утилита, оказавшаяся вне `PATH`, получает подсказку (`fish_add_path ...`), и её настройки git остаются
  выключенными, пока утилита не найдётся.

### Откуда берутся наборы

```
./pack add git                      # набор boosh: из этого репозитория или скачивается из каталога
./pack add PatrickF1/fzf.fish       # любой плагин с GitHub, как в fisher: OWNER/REPO[@тег|ветка|коммит]
./pack add github:OWNER/REPO@v1.2   # то же самое, полной записью
./pack add https://host/x.tar.gz    # архив
./pack add ./my-plugin              # папка (разработка, офлайн)
./pack show OWNER/REPO              # сначала посмотреть: ничего не устанавливает
./pack update [ИМЯ]                 # скачать заново и применить (без имени: все установленные)
./pack list --remote                # показать и наборы каталога
```

- **База и наборы живут раздельно.** В этом репозитории установщик и инструмент `pack`; сами наборы лежат в
  репозитории-каталоге [booosh-packs](https://github.com/Bopster410/booosh-packs). Он указан в `packs.conf`
  (`CATALOG=github:Bopster410/booosh-packs@main`, либо переменная окружения `BOOSH_CATALOG`, которой можно дать и
  локальную папку). `./pack add ИМЯ` скачивает набор при первом использовании; установленные наборы работают без сети
  (это снимки в `~/.local/share/booosh/packs/`). Для воспроизводимой установки закрепи каталог на полном хеше коммита
  (`@<40 hex-цифр>`): ветка и тег могут сдвинуться.
- **Раскладка fisher понимается.** Плагину не нужен `pack.conf`: его `conf.d/`, `functions/`, `completions/` и
  `themes/` линкуются по файлам, а события `NAME_install`, `NAME_update`, `NAME_uninstall` отправляются так же, как это
  делает fisher (`PatrickF1/fzf.fish` ставится как набор `fzf-fish`, имя события `fzf`). Это не замена fisher: файла
  `fish_plugins` нет, поэтому не ставь один и тот же плагин обоими способами.
- **Чужой код считается чужим.** Всё, что не набор boosh, показывается (источник, sha256 архива, каждый файл, утилиты)
  и требует «да» (`--yes` пропускает вопрос). Используется только https, архив с символическими ссылками
  отклоняется, а `pack` останавливается до любых изменений, если файл уже принадлежит другому набору или prompt-у
  boosh. Откуда пришёл набор записано в `~/.local/share/booosh/packs/ИМЯ/.source`.

Наборы каталога: **git** (аббревиатуры `gst`, `gd`, `gcm`, `gl`, git-информация в prompt-е boosh (ветка, впереди/позади, индекс, изменения, неотслеживаемые, stash; считается в фоне) и в стандартном prompt-е fish и несколько безопасных настроек:
`init.defaultBranch`, `push.autoSetupRemote`, `fetch.prune`, `rerere.enabled`, а также настройки вывода и удобства вроде `merge.conflictStyle=zdiff3`, `diff.algorithm=histogram`, `branch.sort=-committerdate`, `tag.sort=version:refname`; поведение `pull` пак не меняет), и необязательная часть `--tag`: `./pack add git --tag` добавляет `gtag patch|minor|major` (следующий semver-тег; спрашивает перед созданием, ничего не отправляет) и **docker** (аббревиатуры `d`, `dps`,
`dex`, `dcup`, `dcl`; `docker compose` или `docker-compose` определяется при нажатии пробела, поэтому запуск оболочки
остаётся быстрым).

## Prompt

В boosh есть свой небольшой prompt для fish (`fish/prompt/`, несколько сотен строк с комментариями и командой настройки). Менеджер плагинов не нужен.

```
~/app main ⇡1 ⇣1 +2 !1 ?3 ✖1 *1 5s
❯
```

- **Строка 1**: путь, статус git и время медленной команды (3 с и больше). **Строка 2**: символ; после неудачной
  команды он краснеет и показывает код выхода (`✘1 ❯`). Между выводом команды и следующим prompt-ом стоит пустая
  строка (перед самым первым prompt-ом её нет).
- **Git-информация приходит с набором `git`** (`./pack add git`); без него в prompt-е просто нет git-части, а
  `boosh-prompt --git/--fields` подскажут добавить набор. **Считается она в фоне.** Один вызов `git status --porcelain=v2` идёт в отдельном процессе, поэтому prompt его не ждёт:
  данные появляются чуть позже, и prompt перерисовывается сам. Обозначения: `⇡ ⇣` коммиты на отправку и получение,
  `+` в индексе, `!` изменено, `?` не отслеживается, `✖` конфликты, `*` stash. Отсоединённая голова даёт `@abc1234`.
- **Цена.** В одном замере (запуск fish плюс работа перед prompt-ом, маленький репозиторий / 30 000 файлов): 26 / 27 мс,
  [Hydro](https://github.com/jorgebucaran/hydro) 28 / 30 мс. В пределах шума этого замера они равны, и время не растёт
  с размером репозитория. Стандартный синхронный git-prompt fish: 36 / 50 мс.
- **Настраивается одной командой** `boosh-prompt` (есть автодополнение). Изменения действуют на следующий prompt во всех
  открытых терминалах и остаются после перезапуска; при неверном флаге не меняется ничего:

  | Команда | Что делает |
  |---|---|
  | `boosh-prompt` | показать текущие настройки (`*` отмечает изменённое) |
  | `--lines 1\|2` | одна или две строки |
  | `--gap N` | пустых строк между prompt-ами, от 0 до 5 |
  | `--symbol TEXT` | символ последней строки, например `">"` или `"λ"` |
  | `--path short\|full` | `~/a/b/c` в сокращённом или полном виде |
  | `--git on\|off` | информация git; `off` ещё и полностью останавливает фоновую задачу |
  | `--fields LIST` | части git через запятую, **в указанном порядке**: `branch ahead behind staged modified untracked conflicts stash` |
  | `--time on\|off`, `--time-after 3s` | время медленных команд и что значит «медленная» (`3s` или `3000` мс) |
  | `--status on\|off` | код выхода (`✘1`) после неудачной команды |
  | `--reset` | вернуть значения по умолчанию |

  Флаги можно комбинировать: `boosh-prompt --lines 1 --gap 0 --fields branch,modified,untracked`.
  Настройки это универсальные переменные `boosh_prompt_*`; символы и цвета git-части лежат в одной функции
  набора git, `__boosh_git_format`.
- **Установка и удаление**: `./install.sh --only prompt`, либо `--prompt default`, чтобы вернуть стандартный prompt fish.
  Если установлен Hydro, Tide или Pure, boosh не спорит с ними за `fish_prompt`, а просит сначала убрать плагин.
- Приём (результат приходит сигналом, потом перерисовка) тот же, что у Hydro; код отдельный.

## Безопасное применение

То, что читают оболочка и Ghostty, лежит в **стабильном ядре**, а не в твоём клоне репозитория:

```
~/.local/share/booosh/
├── core -> generations/0007-...     текущий снимок; всё установленное ссылается через него
├── generations/0006-..., 0007-...   полный снимок на каждую установку (хранятся последние 5)
├── packs/git, packs/docker          снимки установленных наборов (с файлом .source: откуда пришёл)
├── cache/                           скачанный каталог (копия; удалить её безвредно)
└── manifest                         что boosh куда положил
```

- **Репозиторий это только источник.** Смена ветки, перенос, переименование или удаление не ломают установленное (тесты
  ставят из копии репозитория, удаляют копию и проверяют, что все ссылки живы).
- **Собрать, проверить, потом применить.** `install.sh` собирает весь снимок во временной папке, проверяет его
  (`ghostty +validate-config` вместе с твоим `local.conf`, `fish --no-execute` для каждого файла prompt-а) и только потом
  делает текущим и трогает твои файлы. Ошибка останавливает работу до каких-либо изменений.
- **Твои файлы остаются твоими.** `~/.config/ghostty/local.conf` создаётся один раз и не перезаписывается; он
  подключается последним, поэтому всё в нём побеждает. Если у тебя уже есть конфиг Ghostty, boosh сохраняет его как этот
  `local.conf` (твои настройки продолжают действовать поверх настроек boosh) и ещё оставляет копию `.bak`.
  `--import-config no` только делает резервную копию.
- **Всё обратимо.**

| Команда | Что делает |
|---|---|
| `./install.sh --check` | проверка здоровья: битые ссылки, файлы, которые ты правил, репозиторий впереди установленного (код выхода 1 при проблемах) |
| `./install.sh --generations` | список поколений (`*` = текущее) |
| `./install.sh --rollback` | вернуться к предыдущему поколению (конфиг, prompt, стили) |
| `./install.sh --uninstall` | убрать установленное boosh и вернуть твои сохранённые оригиналы; отредактированный тобой `local.conf` остаётся |

Папка данных: `$XDG_DATA_HOME/booosh` (по умолчанию `~/.local/share/booosh`); `BOOSH_HOME` переносит её,
`BOOSH_KEEP_GENERATIONS` меняет число хранимых снимков. Пока не покрыто: файлы редактора (`~/.vimrc`, `~/.nanorc`)
по-прежнему ссылаются в репозиторий; `--check` об этом предупреждает.

## Что куда записывается

| Путь | Кто пишет | Что |
|---|---|---|
| `~/.config/ghostty/config` | `install.sh` | **сгенерирован**, руками не править |
| `~/.config/ghostty/local.conf` | `install.sh` (один раз) | **твой**: создаётся один раз, не перезаписывается, подключается последним (сюда переносится твой старый конфиг) |
| `~/.config/ghostty/gtk.css` | `install.sh` (ссылка в ядро, Linux, `minimal`) | оформление тонкого заголовка |
| `~/.config/ghostty/cheatsheet.md` | `install.sh` | твоя шпаргалка |
| `~/.config/ghostty/.install-choices` | `install.sh` | последние ответы (значения по умолчанию при следующем запуске) |
| `~/.config/fish/conf.d/00-boosh-core.fish` | `install.sh` | `set -gx EDITOR ...` |
| `~/.config/fish/functions/` (`fish_prompt`, `boosh-prompt`, вспомогательные), `conf.d/boosh_prompt.fish`, `completions/boosh-prompt.fish` | `install.sh` (ссылки в ядро) | prompt boosh |
| `~/.vimrc` или `~/.nanorc` | `install.sh` (симлинк) | конфиг редактора |
| `~/.config/fish/conf.d/pack-<имя>.fish` | `pack` (ссылка в снимок набора) | аббревиатуры |
| `~/.config/git/pack-<имя>*.conf` + `include.path` в `~/.gitconfig` | `pack` | настройки git |
| `~/.config/boosh/packs` | `pack` | список установленных наборов (на каждой машине свой) |
| `~/.local/share/booosh/` | `install.sh`, `pack` | стабильное ядро, поколения, снимки наборов и манифест (см. выше) |

Всё, что уже существует, переносится в `<имя>.bak` (или `.bak.1`, ...) перед заменой. `~/.bashrc`, `~/.profile` и
твоя git-идентичность не трогаются.

Правки под конкретную машину делай в `~/.config/ghostty/local.conf` (он твой): сгенерированный `config` переписывается при
каждом запуске.

## Расширение

- **Редактор**: создай `editors/<имя>/` с `editor.conf` (`DESCRIPTION`, `COMMAND`, `FILE`, `TARGET`) и файлом
  конфига. В меню он появится сам.
- **Набор**: добавь папку в репозиторий-каталог, как описано выше (проверить до публикации можно так: `BOOSH_CATALOG=./my-catalog ./pack list` или `./pack add ./my-pack`).
- **Пресет внешнего вида**: добавь `ghostty/appearance/<имя>.conf` и имя в `PRESETS` в `install.sh`
  (и подсказку в `menu_desc`).
- **Пресет шорткатов**: добавь `ghostty/keys/<имя>.conf` (`@MOD@` для модификатора) и имя в `KEYSETS`.
- **Короткое имя темы**: одна строка в `theme_spec` в `install.sh`; любое имя темы Ghostty и так работает через `--theme`.

## Совместимость

Разработано и проверено на **Ubuntu 24.04, GNOME (Wayland), Ghostty 1.3.1, fish 4.9.3, bash 5.2**.

- **macOS**: ветки для macOS (`local.macos.conf`, Homebrew, `macos-titlebar-style`) написаны по документации Ghostty
  и **на Mac не запускались**. Код обходится без возможностей bash 4, так что системный bash 3.2 должен подойти, но
  это тоже не проверено.
- **Windows**: используй WSL2 и запускай всё внутри него.
- Живой курсор и цветные предпросмотры требуют терминала, который понимает `DECSCUSR` и 24-битный цвет; Ghostty
  понимает.
- Аббревиатуры fish с маркером курсора требуют fish 3.6 и новее. Prompt использует встроенную команду `path` (fish 3.5+,
  по документации); проверен только на fish 4.9.3.
- Сами буквы шрифта показать нельзя: терминал рисует весь текст одним шрифтом, поэтому показываются только сведения.
- Команды `uninstall` пока нет: удали перечисленные выше симлинки и верни файлы `.bak`.

## Тесты

```bash
bash tests/smoke.sh                       # запускается во временном $HOME
BOOSH_TEST_PTY=1 bash tests/smoke.sh      # плюс прогон меню со стрелками через pty (Linux)
```

Тесты покрывают флаги установщика и проверку значений, повторный запуск, `--dry-run`, шпаргалку, механику `pack`
(ссылки, подключение git, конфликты, защиту для `delta`, необязательные части, каталоги, источники GitHub и папки,
плагины в стиле fisher и их события, коллизии), сам prompt и стабильное ядро (поколения, откат, перенос старого
конфига, удаление, `--check`, а также то, что всё работает после удаления репозитория). Используются крошечный
каталог-фикстура (`tests/fixtures/catalog`) и подставной `curl`, поэтому сеть не нужна. `ghostty` и `fish` для них не
нужны: проверки, которым они нужны, пропускаются. Содержимое настоящих наборов (`gtag`, `gsync`, настройки git,
git-часть prompt-а и её разбор) проверяется в репозитории [booosh-packs](https://github.com/Bopster410/booosh-packs).
